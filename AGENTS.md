# AGENTS.md

## Supabase Database & Table Access Rules

앞으로 Supabase에서 테이블을 생성하거나 액세스할 때는 아래 규칙을 항상 적용합니다.

1. **PostgREST API 접근 권한 (`GRANT`) 명시**
   - `anon`과 `authenticated` 역할(Role)이 PostgREST API를 통해 해당 테이블에 접근할 수 있도록 명시적인 `GRANT` SQL 문을 반드시 포함합니다.
   - 필요에 따라 `SELECT`, `INSERT`, `UPDATE`, `DELETE` 권한(및 시퀀스 사용 시 `USAGE, SELECT ON ALL SEQUENCES`)을 명시적으로 부여합니다.

2. **RLS(Row Level Security) 활성화 및 인증 사용자 정책(`Policy`) 필수 작성**
   - 모든 테이블에 `ALTER TABLE ... ENABLE ROW LEVEL SECURITY;`를 적용하여 RLS를 활성화합니다.
   - 기본적으로 인증된 유저(`authenticated`)만 읽고 쓸 수 있도록 `CREATE POLICY`를 함께 작성합니다. (사용자별 소유권 격리가 필요한 경우 `auth.uid() = user_id` 조건을 추가로 적용합니다.)

---

### 표준 SQL 템플릿 (Standard Template)

```sql
-- 1. 테이블 생성 예시
CREATE TABLE IF NOT EXISTS public.example_table (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE DEFAULT auth.uid(),
  content TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 2. PostgREST API 접근을 위한 명시적 GRANT
GRANT USAGE ON SCHEMA public TO anon, authenticated;
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLE public.example_table TO anon, authenticated;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO anon, authenticated;

-- 3. RLS(Row Level Security) 활성화
ALTER TABLE public.example_table ENABLE ROW LEVEL SECURITY;

-- 4. 인증된 유저(authenticated)만 읽고 쓸 수 있는 Policy 작성
CREATE POLICY "Authenticated users can select"
  ON public.example_table
  FOR SELECT
  TO authenticated
  USING (auth.uid() IS NOT NULL);

CREATE POLICY "Authenticated users can insert"
  ON public.example_table
  FOR INSERT
  TO authenticated
  WITH CHECK (auth.uid() IS NOT NULL);

CREATE POLICY "Authenticated users can update"
  ON public.example_table
  FOR UPDATE
  TO authenticated
  USING (auth.uid() IS NOT NULL)
  WITH CHECK (auth.uid() IS NOT NULL);

CREATE POLICY "Authenticated users can delete"
  ON public.example_table
  FOR DELETE
  TO authenticated
  USING (auth.uid() IS NOT NULL);
```
